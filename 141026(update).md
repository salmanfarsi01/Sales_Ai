### C. Elimination of Fail-Open Risk via Mandatory Snapshot Parameter

`snapshot: Any` is a **mandatory required parameter** with NO default across all decision validation and binding lookup functions in [copilot/core_decision_manager.py](file:///C:/dev/Sales_Ai/copilot/core_decision_manager.py):
1. **`StrategicDecisionCache.validate_evidence_consistency(decision, snapshot, require_active=True)`**:
   - If `snapshot is None`, fails closed: returns `(False, "Missing snapshot: snapshot is mandatory for evidence consistency validation")`.
2. **`StrategicDecisionCache.get_strictly_bound(call_sid, turn_id, source_state_version, source_event_id, state_call_sid, snapshot, require_active=True)`**:
   - `snapshot` has no default. If `snapshot is None`, returns `None`. Omitting raises `TypeError`.
3. **`StrategicDecisionCache.validate_binding(decision, call_sid, turn_id, source_state_version, source_event_id, state_call_sid, snapshot, require_active=True)`**:
   - `snapshot` has no default. If `snapshot is None`, returns `(False, "Missing snapshot: bound ConversationStateSnapshot is mandatory for binding and evidence validation")`. Omitting raises `TypeError`.

   - `snapshot` has no default.

### F. Root Cause of Cross-Run ID Mismatches & Event ID Determinism

**Root Cause**: In simulations, event IDs are derived deterministically: `ev_turn_{turn}_v{version}`. When `sim_muy04bh0` was run twice without clearing the in-memory cache, Run 2 collided with Run 1 on all 4 keys `(call, turn, version, event)`, returning Run 1's cached decision with Run 1's randomized UUIDs (`fact_7049325b`).

**The 3 Invariants**:
1. `ConversationReplayEngine.replay_call` clears the cache for that `call_sid` at initialization.
2. `StrategicDecisionCache.get_strictly_bound` validates evidence references against the bound `snapshot`. Even if a call SID is reused without clearing the cache and event IDs collide, Run 2's snapshot contains different UUIDs, the stale cache entry is rejected, and a fresh decision is evaluated.
3. In `ConversationReplayEngine.replay_call`, any unexpected evidence mismatch is recorded in `step.evidence_warnings` and `decision.reason_codes`, and falls back to a fresh evaluation.
